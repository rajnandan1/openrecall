# openrecall · v0.3.0 · a plugin for claude code

Claude picks up where you left off.

A new Claude Code session starts blank. OpenRecall hands it what the last session on the same branch knew: the goal, the ticket, the PR, the commands that worked and what you asked last. It runs locally, in a few milliseconds, with no model call before Claude answers.

# how it works

Four hooks, one binary, plain files.

OpenRecall hooks into Claude Code at four moments and keeps everything as Markdown on your disk.

# the gate

It adds little, and only when it matches.

A handoff record once per context window. At most three memory lines per prompt. Nothing at all for short prompts.

# speed

No model call between your prompt and Claude's answer. The hook adds a few milliseconds.

# architecture

What runs, and when.

The plugin holds no code. It tells Claude Code to run one binary, openrecall, at four moments of a session. Only the prompt step runs before Claude answers. The other steps run in the background.

# extraction, optional

Facts that write themselves, if you want them.

Off until you add an API key for any OpenAI-style endpoint. After a session ends, or after 30 quiet minutes, a background worker writes the facts that a later session would need. It never runs between your prompt and Claude's answer.

# install

Install in three commands.

You need macOS on Apple silicon. The first command checks the SHA-256 hash of the binary and needs no Rust.

  1. 01Open Claude Code in a git repo, on any branch except main or master.
  2. 02Send one prompt and wait for the answer.
  3. 03Run find ~/.openrecall/repos -path '*/handoffs/*.md'. You see the record for your branch.

# faq

Questions.

does openrecall send my code anywhere?

No. Memories and handoff records stay in ~/.openrecall/. Only extraction sends text out, to the provider that you choose, and it is off until you configure it.

does it slow down my prompts?

OpenRecall calls no model between your prompt and the start of Claude's answer. The hook adds a few milliseconds. The status line shows the time, for example recall 3 · 4 ms.

how much context does it add?

At most one handoff record of about 800 tokens, once per context window. On each prompt, at most 3 memory lines of about 400 tokens in all. Often it adds nothing, because nothing passed the gate.

does it change claude.md or claude code's built-in memory?

No. OpenRecall reads the built-in memory and never writes there. Extraction writes suggested rules to claude-md-suggestions.md, and you copy the ones that you want by hand.

how does it update?

In the background, at most once in 24 hours. It checks the SHA-256 hash of each new binary. To turn it off, set OPENRECALL_UPDATE to 0 in the env key of ~/.claude/settings.json.

how do i remove it?

Run claude plugin uninstall openrecall@openrecall, then delete ~/.local/bin/openrecall. To delete every memory and handoff record too, delete ~/.openrecall. You cannot undo that step.
